## Comparison write Up
The R and ChatGPT approached were mostly in agreement. As noted in AU_USAGE.md, for the sample data, AI failed to clean the site column. R was more consistent, but it ultimately took longer. I did feel more confident in results produced by R, because I was able to validate them myself – where in a document uploaded to generative AI would need to be extensively reviewed to ensure nothing was changed. The same agreement was also noted in the sequence data. One thing ChatGPT did differently, was that it added QC flags and summaries of what was changed. In real data practice, this is extremely important and valuable. 
The were two main cases of failure. In the R instance, the DOB column was parsed incorrectly, so there were dates set in future years (i.e. 2053). In future, validation would ensure that all DOB’s occur in the past. Additionally, two glucose values include astericks, which caused numeric detection issues. During the first run, these numbers were coerced into Nas, but after removal of the *, they remained as true values. Lastly, in the FASTA file, some of the stated lengths did not match the actual sequence length. To note, it took me several runs and re-runs to diagnose and correct the errors, where AI caught all 3 in the first go. 
For a real-world dataset, I would trust R and regex for the final cleaning pipeline because it can be tailored to specific data demands, alongside being reproducible. Although, with how efficient and correct AI was in this instance, I would use AI mainly as a second line of QC.
## Samples × features × metadata
The cleaned sample data was already formatted as one row per sample, so ultimately no pivot was needed. I used the glucose value as the main feature and kept DOB, sex, site, and glucose unit as the metadata. It could be used for modeling after review for outliers, correct metadata format (DOB, unit, etc). Missing values should also be considered.
